# QuickServe — Database documentation

Schema source of truth: `supabase/001_schema.sql` (run in the Supabase SQL
editor). Everything below is a reference summary.

## Tables

### `public.profiles`
Extends `auth.users` with product identity and **role**.

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | `uuid` PK | FK `auth.users(id)` ON DELETE CASCADE |
| `full_name` | `text` | default `''`; populated from `raw_user_meta_data` |
| `phone` | `text` | nullable |
| `role` | `public.user_role` | enum `customer / agent / admin`, default `customer` |
| `created_at` | `timestamptz` | default `now()` |

Auto-created on every sign-up by `handle_new_user()` (trigger on `auth.users`).

### `public.services`
Catalog of sellable services (seeded: AC Servicing, Plumbing, Electrical, Cleaning).

| Column | Type | Notes |
| ------ | ---- | ---- |
| `id` | `uuid` PK | `gen_random_uuid()` |
| `name` | `text` UNIQUE | |
| `description` | `text` | |
| `active` | `boolean` | non-active hidden from non-admins by RLS |
| `created_at` | `timestamptz` | |

### `public.service_requests`
The core entity.

| Column | Type | Notes |
| ------ | ---- | ---- |
| `id` | `uuid` PK | |
| `request_code` | `text` UNIQUE NOT NULL | `REQ-YYYY-######`, generated by trigger |
| `customer_id` | `uuid` NOT NULL FK→profiles | requester |
| `service_id` | `uuid` NOT NULL FK→services | |
| `assigned_agent_id` | `uuid` NULL FK→profiles | only admins may set |
| `description` | `text` NOT NULL | ≥ 5 chars (RPC check) |
| `preferred_at` | `timestamptz` NOT NULL | must be in the future (RPC check) |
| `address` | `text` NOT NULL | ≥ 5 chars (RPC check) |
| `priority` | `public.request_priority` | `low / medium / high`, default `medium` |
| `status` | `public.request_status` | default `created`; transitions validated by trigger |
| `notes` | `text` | work notes written by agents |
| `created_at` / `updated_at` | `timestamptz` | `updated_at` bumped by trigger |

### `public.request_status_history`
Immutable changelog, one row per transition.

`id` (identity PK), `request_id` FK→service_requests ON DELETE CASCADE,
`old_status`, `new_status` (NOT NULL), `changed_by` FK→profiles, `note`,
`created_at`.

### `public.audit_logs`
Immutable security-relevant events.

`id` (identity PK), `actor_id` FK→profiles, `request_id` FK nullable,
`event_type` text, `metadata` jsonb, `created_at`.

Allow-listed events: `LOGIN_SUCCESS`, `LOGIN_FAILED`, `LOGOUT`, `REQUEST_CREATED`,
`REQUEST_ASSIGNED`, `REQUEST_UPDATED`, `REQUEST_CANCELLED`, `AUTHORIZATION_FAILED`,
`DATABASE_ERROR`.

## Request lifecycle (enforced)

```text
created      → assigned | cancelled
assigned     → accepted | cancelled
accepted     → in_progress
in_progress  → completed
completed    → (terminal)
cancelled    → (terminal)
```

Enforced by `validate_status_transition()` **BEFORE UPDATE** trigger — applies to
every writer, admins included.

## Indexes & rationale

| Index | Purpose |
| ----- | ------- |
| `idx_requests_customer` | “my requests” for customers |
| `idx_requests_agent` | “my assigned work” for agents |
| `idx_requests_status` | admin status filtering / dashboard counts |
| `idx_requests_created (desc)` | default ordering (newest first) |
| `idx_history_request` + `idx_history_changed_by` | details-screen timeline |
| `idx_audit_created (desc)` + `idx_audit_actor` + `idx_audit_event` | audit feed + diagnostics |

## Server-side functions (RPCs)

| Function | Type | Purpose |
| -------- | ---- | ------- |
| `create_request(...)` | SECURITY INVOKER | validated insert; RLS still applies |
| `update_request_status(id, new_status, note)` | SECURITY DEFINER | the ONLY sanctioned status path for agents/customers; ownership + role + transition checks, writes history/audit via triggers |
| `write_audit(event, request?, metadata?)` | SECURITY DEFINER | allow-listed audit insert |
| `current_user_role()` | SECURITY DEFINER | trusted role lookup |
| trigger fns: `generate_request_code`, `touch_updated_at`, `handle_new_user`, `validate_status_transition`, `prevent_role_escalation`, `record_request_history` | — | behavioral enforcement |

## Constraints summary

- FK integrity everywhere; `request_code` unique; enums constrain domains.
- `audit_logs` has **no INSERT policy** — only SECURITY DEFINER functions write.
- Neither `request_status_history` nor `audit_logs` can be deleted/updated by any
  client role under RLS (no DELETE/UPDATE policies exist).
